## 大批量导出验证（2026-11-12）

环境：Linux（WSL2），Python 3.13.18，Flask 3.1.3、Pillow 13.0.0、NumPy 2.5.4、Waitress 3.0.2。

- **内存不随压缩包增长**：使用 `scripts/benchmark_batch_export.py` 生成 16 张确定性 3000×2000（6 MP）PNG 源图。8 张生成 85.11 MB 压缩包，导出阶段峰值内存 +0.0 MB；16 张生成 170.39 MB 压缩包，峰值内存仍为 +0.0 MB。压缩包翻倍而工作内存不变，说明实现逐张编码写入磁盘、未在内存中组装整个 ZIP。
- **并发可用**：准备 12 张大图期间持续请求某张素材的缩略图，共完成 147 次读取，中位耗时约 2.5 ms，说明普通浏览请求未被长时间阻塞。
- **完整才可下载**：未完成的任务下载返回 409；`completed` 后的下载经真实 Waitress HTTP 请求得到 1,046,646 字节，`Content-Length` 一致，ZIP 可解压、`testzip()` 无错误、清单数量为 12。
- **中断清理**：真实 HTTP 连接只读取 64 字节后断开，任务转为 `failed`（`download_interrupted`，记录已读/总字节），对应 ZIP 与 `exports` 记录被删除。
- **取消/失败清理**：取消与模拟编码异常后，`data/exports/.staging/` 为空，没有遗留 `.zip`，也没有 `kind=archive` 的失效记录。
- **格式一致**：逐一比对单独导出与 ZIP 成员，字节完全相同（PNG/WEBP 等）；GIF、TIFF、BMP、JPEG 成员均可重新解码，尺寸与模式正确；PNG 保留透明通道。
- **自动化**：新增 `tests/test_exports.py` 覆盖进度、顺序、取消、失败、中断下载、格式一致、并发拒绝、重启中断、内存不随压缩包增长等场景。
